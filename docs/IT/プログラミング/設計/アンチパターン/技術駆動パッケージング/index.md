# 技術駆動パッケージング
以下はECサイトのフォルダ構成を表したもの。

このような設計パターンや技術的な特徴が似ている者同士のフォルダ分け、パッケージ分けを**技術駆動パッケージング** という

多くのWebフレームワークはMVCアーキテクチャを採用していて、デフォルトでmodels、views、controllersとなっている。フレームワークの標準構造が技術駆動パッケージングであるためか、それをお手本に内部の様々なフォルダ構造も技術駆動パッケージングになりがち。

業務上の概念を表すクラスを業務クラスと呼ぶ。業務クラスを技術駆動パッケージングでフォルダ分けすると、本来強く関係し合うファイル同士がパラパラになり混乱する。

業務クラスは概念と強く関係し合う者同士が一緒になるようにフォルダ分けした方が良い。

こうすることでpackage privateにもでき、無関係なユースケースから参照される危険性を防げる。

- 設計ごとにフォルダ分け
    - どれが強く関係しあうか分からない。
    - 誤った用途以外のものと結びつけられてしまう可能性がある。
- 概念の種類ごとにフォルダ分け
    - 強く関係し合うクラス同士が一目でわかるようになる。
    - 情報隠蔽が可能になる（package private）

```text title="設計ごとにフォルダ分け"
├─Entites
│      入庫エンティティ.java
│      出庫エンティティ.java
│      注文エンティティ.java
│      発注エンティティ.java
│      請求エンティティ.java
│      買い物かごエンティティ.java
│
├─UseCases
│      在庫ユースケース.java
│      支払いユースケース.java
│      注文ユースケース.java
│
└─ValueObjects
        クレジットカード番号.java
        割引ポイント.java
        在庫回転期間.java
        安全在庫量.java
        注文先.java
        発注金額.java
        請求金額.java
```

```text title="概念の種類ごとにフォルダ分け"
├─在庫
│      入庫エンティティ.java
│      出庫エンティティ.java
│      在庫ユースケース.java
│      在庫回転期間.java
│      安全在庫量.java
│      発注エンティティ.java
│      発注金額.java
│
├─支払い
│      注文エンティティ.java
│      注文ユースケース.java
│      注文先.java
│      買い物かごエンティティ.java
│
└─注文
        クレジットカード番号.java
        割引ポイント.java
        支払いユースケース.java
        請求エンティティ.java
        請求金額.java
```
