# Docker
## Docker Engine
Dokerのソフトウェア。

コンテナを作ったり、動かしたりできる。

## image
コンテナを作る元になる。

Apacheのコンテナを作りたいならApacheのイメージ、MySQLを作りたいMySQLのイメージを使う。

## DockerはLinuxマシンを使う
Dockerを使うには、Linux OSが必要。

コンテナに入れるプログラムもLinux用のプログラムでないといけない。

## コンテナを持ち運べる
コンテナを一度書き出して別のDocker上に再構築することができる。

コンテナを全員に配布し、開発環境を一斉に整えたりできる。

Dockerさえ入っていれば良いから、OSが違う場合でも意識する居ことなくコンテナを移動できる。

Dockerがあれば、本番サーバと開発サーバでの**物理的な環境の違いや、サーバ構成の違いを無視できる**

## コンテナからもイメージが作れる
イメージからコンテナが作れるだけでなく、コンテナからイメージを作ることもできる。

作成したコンテナに手を加えて、そのイメージを新たに作れるということ。

## Docker Hubとイメージ
コンテナのイメージは、初心者が1から作ることは滅多にない。

よく使われるイメージは既に用意されている。

「Docker Hub」は公式が運用しているDockerレジストリ（Dockerのイメージの配布場所）

https://hub.docker.com

## Docker Hubではどんなイメージが公開されているか
ソフトフェア単体で配布されているものもあれば、ソフトフェアが複数入ったもの物まである。

- OS（っぽいもの）
- OS（っぽいもの） + Apache
- OS（っぽいもの） + Apache + MySQL

## 安全なコンテナイメージの選び方

- 公式が出しているものを使う。
- 自分でカスタムする
    - 必要最低限のものが入ったコンテナを選択して、そこへ自分でソフトウェアをインストールする。

# 特徴

- 1コンテナ=1アプリ
    - セキュリティ面、メンテナンスのしやすさから、1つのコンテナに1アプリのみ入れて運用することが推奨されている。

## Dockerコンテナのライフサイクルとデータの保存
Dockerコンテナは作って捨てるが基本
「作る」→「起動する」→「停止する」→「破棄する」→「作る」という一連の流れを「コンテナのライフサイクル」という。

## データの保存
コンテナを破棄するとコンテナ内のデータは消えてしまうため、データは物理マシンのディスクにマウントする
