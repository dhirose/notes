# Rustとは
## システムプログラミング言語

Rustはシステムプログラミング言語

CやC++といった言語が担ってきた、OSの基盤やブラウザなどの低レイヤーなソフトウェア開発を、より安全な形で実現することを目的として設計された

## Rust for Linux

Linuxカーネル開発においてRustの利用を可能にすることを企図取り組みであり、しょうらり的にはカーネル内部にRustで実装されたコンポーネントが導入される可能性がある

## Web バックエンド開発

システムプログラミングの範疇を超え、バックエンド開発もできる。

バックエンド開発が最も主要な利用事例であるとの結果もある

## Rustの特徴

- 信頼性
    - メモリ安全性
    - 並行処理安全
    - 未定義動作を起こさないことを保証している
- 並行処理安全性
- 高パフォーマンス

### 信頼性

- メモリ安全性
- 並行処理安全

従来のプログラミング言語で遭遇するようなダングリングポインタやuse-after-treeといったメモリにバグや、データ競合といった並行処理にまつわるバグを未然に防ぐことができる。

こうしたバグは「未定義動作」を引き起こし脆弱性につながることもあるが、Rustはこのメモリ安全と並行処理安全をコンパイル時に保証し、開発の早い段階で防ぐことができる。

独自の仕組みである所有権やライフタイム、トレイトによる細かい制御によって防ぐ。

### 速度

ランタイムを持たずコンパイル後は直接機械語に翻訳されるため、オーバーヘッドが少ない。

従来のプログラミング言語は、安全性とパフォーマンスはトレードオフの関係にあった。
Rustはその独自の言語設計により、このトレードオフを克服した言語。

#### 従来の方法

- メモリ管理の実現
    - ガベージコレクション
        - 不要になったメモリ領域が解放されるタイミングはガベージコレクションに委ねられるため、処理のパフォーマンスにぶれが出る。
        - そもそもその部分を制御できない。
- 高パフォーマンスの実現
    - メモリ管理
        - メモリ確保、解放をプログラマ自身で行うことにより高パフォーマンスを実現できるが、プログラムが複雑化してセキュリティ上の問題を抱えやすい。

### 生産性

以下のような文法レベルの生産性がある。

- null安全性を確保するためのOption<T>型
- エラーハンドリングを行うためのResult<T, E>型
    - 従来の例外機構を持つプログラミング言語の課題を巧みに回避したエラーハンドリングらしい。

クロスプラットフォーム対応で、他の言語のように仮想マシンを持たないが、多くのプラットフォーム向けのバイナリをビルドして配布することができる。

#### Cargo

ビルド兼パッケージ管理マネージャー

コンパイルやテストの実行、さらにはライブラリ（Rustでは、「クレート(crates)」と呼ぶ）の公開までできる。

Rustのクレートはcrates.ioというレジストリに公開されている
このレジストリに公開されたエコシステムにCargoによる設定一つでアクセスすることができる。

#### rust-analyzer（Language Server）

rust-analyzerによって、Rsutの開発者は自身の好きなエディタで開発することができる。
